# GridWorld — project rules

Browser FPS in a green vector-grid style (wireframe on black, retro sci-fi / Tron / CRT terminal).
`legacy/grid-arena.html` is the original single-file version (from when the game was called Grid Arena), kept as the reference for behaviour.

## Commands
- `npm run dev` — dev server (Vite)
- `npm test` — Vitest (generators, terrain, saves)
- `npm run typecheck` / `npm run build`
- `npm run serve` — the dedicated server (`server/main.mjs`: the built game + multiplayer on `PORT` 8517; see `SERWER.md`, `deploy/install.sh`)
- `npm run sim` — headless simulations in `tools/` (`tools/sim.config.ts`, files `*.sim.ts`): `tools/growth.sim.ts` runs every village of a world through village life (`SIM_WORLD`, `SIM_DAYS`, `SIM_EVERY` env vars) and prints population, food, gold, buildings, raids and the food price; `tools/civ.sim.ts` runs the civilisation layer (`SIM_PLAYERS=0,4`); `tools/materials.sim.ts` regenerates `SUROWCE.md` (the owner's Polish guide to every material, processing, build and an index of uses, straight from the data: rerun it after changing recipes, needs or items; `SUROWCE.pdf` is the same rendered to A4 through Chromium (markdown → HTML with the `markdown` Python package, then Playwright `page.pdf`): regenerate it with the .md); `tools/campaign.sim.ts` walks a player bot through the campaign (restoring the old plants it needs, finding their plans, waiting on batches, order income; time and gold by category), times it and calibrates the Chariot's size to `TARGET` 100 h alone (`PACE` = the assumptions about gold per hour, speeds, dive times; batches are in game minutes, a game hour is a real minute); `tools/balance.sim.ts` prints the economy's numbers (a crate of each old plant's goods in inputs and fuel, order margins, restoration, improvement and Chariot costs; `tools/worth.ts` values a crate); `tools/uses.sim.ts` lists goods and materials with fewer than 2 uses. Economy stage 8 (balance) is paused by the owner: a draft of changes is kept in `tools/stage8-draft.patch` (see `PLAN_GOSPODARKI.md`).
- Dev console: ~ (Backquote) opens it in every build (`ui/console.ts`): `cash` (+10000 gold), `god` (full health + immortality, toggle), `home` (back to Gridholm), `time [hour]` (show the clock / skip ahead), `map` (whole-planet dev map, `ui/devmap.ts`: pan, zoom, click a place, a toxic fog zone or any spot to teleport via `teleportTo` in `world/level.ts`; the fog zones are scanned over the whole planet a slice a frame while it is open (`scanFog`, `fogScan`), a click on one lands at its southern edge), `tp <x> <z>`, `fly [speed]` (dev flight: `G.fly`, `flyStep` in `world/player.ts`: no gravity or collisions, W/S along the view, Space/C up/down, Shift 3x; twice the load radius, fog pushed back, horizon rings hidden, `camera.far` 600, `mayspawn` refuses), `help`, `clear`. Add commands to `COMMANDS` there.
- In a dev build, `window.__game` exposes `{ G, W, camera, scene, renderer }` for debugging; F3 toggles the perf overlay (fps, lines, triangles, draw calls).

## Rules
- **After every finished task** (committed and pushed), end the reply with the download link of the current version: `https://github.com/MrFischoeder/Gridworld/archive/refs/heads/<branch>.zip` (the branch the work was pushed to). Unzip, `npm install`, then `start-gry.bat` or `npm run dev`.
- **Version number:** with every pushed change bump `VERSION` in `src/version.ts` (and `version` in `package.json` to match): the middle number for a new feature (0.5.0 → 0.6.0), the last one for a fix (0.6.0 → 0.6.1); also set `BUILD` (date · what changed) and add an entry at the top of `CHANGELOG` in `src/data/changelog.ts` (version, date, title, player-facing notes in English; shown by the Changelog button in the main menu, `ui/changelog.ts`) — every change, feature or fix, gets described there. The number is shown next to the title in the main menu ("GRIDWORLD v0.5.0") and in the browser tab; say the new number in the reply.
- **Stack:** Vite + TypeScript (strict), three.js from npm. No UI framework: HUD and windows are plain DOM + CSS.
- **Game language: English.** Every player-visible text (HUD, menus, dialogue, items, hints) is English. Identifiers and comments in English.
- **Deterministic generation:** the whole world (dungeons, villages, terrain, ruins, object placement) comes only from seeded RNG (`core/rng.ts`: `rng`, `hash`, noise). Generators **never** call `Math.random()`. `Math.random()` is allowed only for effects and unsaved things (sparks, drone loot, NPC wandering). Same seed + same coordinates = identical result. This is the basis of saves and future multiplayer.
- **Save only player changes** (opened chests, killed bosses, unlocked doors, position, character) — never generated geometry.
- **Visual style:** grid lines `#2fe060`, black background, fog to black (on the surface by day the sky and fog turn a bright hazy green, see the game clock note). Every solid that should hide what is behind it needs a dark fill (e.g. `0x010d04`, see `fillMat()` in `world/render.ts`) with `polygonOffset`, lines on top. Lines without a fill are see-through — a bug, unless the object is meant to be openwork (drones, bosses, pickups).
- **Functional colours:** drones and hostile creatures `#ffb347` (a calm Bramble is olive `#b8b060`), bosses `#ff6a4a`, gold/chests `#ffd060`, stairwells `#5cc8ff`, XP `#9dffe0`, locked doors `#ff5a3c`; water: fresh `#2ac8b0`, murky `#8a9a4a`, toxic `#b6ff3a` (glowing).
- **Controls: desktop only for now** (pointer lock, WASD, mouse). Mobile/touch development is paused: keep the existing touch code (joystick, buttons in `ui/touch.ts`) in place, but new features do not need touch controls, touch layouts or phone testing, and mobile is not considered in design decisions until the owner says otherwise.
- **Performance:** smooth on an average laptop (phones are out of scope while mobile is paused). Measure line/triangle counts (F3) on big changes.
- **Map format:** voxel maps are ordered op lists `{op:'room'|'solid', x,y,z,w,h,d}` (later ops override earlier). The future map editor will save this format — keep it.
- **Multiplayer** (stage 1 relay in place, see the Open world notes; later up to 8 players, Node + WebSocket, authoritative server): keep world logic (`core/`, `gen/`) free of three.js and DOM, generators deterministic, game state serialisable.

Screenshots in `docs/shots/` (1280×720 JPEG, taken with Playwright from the dev build with the HUD hidden). Keep its version and numbers roughly current when big features land.
- `OPIS_GRY.md` (+ `OPIS_GRY.pdf`, rendered like `SUROWCE.pdf`) is the owner's Polish description of the game: concept, story and goal, every system, what is ready and what is not, the plan, and a Polish summary of every version in order. Hand-written: add a line to its history (section 14) and touch the other sections when a big feature lands, then re-render the PDF.
- `PLAN_GOSPODARKI.md` is the agreed staged plan (Polish) for the economy overhaul from the owner's design document: decisions (simplified iron → steel without coke, Ancient Facilities with their own power hall restored in stage II, plans only for tier 2 village works, the game's power scale kept) and stages 1–8 (0.90 raw goods and intermediates → 0.99 balance). Follow it stage by stage; append new rolls, `TECHS` and `INSTALLS` at the end so existing places keep theirs; completed stages in old saves stay completed.

## Layout
- `core/` — pure: RNG/hash, voxel grids, meshing, noise.
- `gen/` — pure generators: dungeon, stairs, village, doors placement, reachability; open world: `regions` (256 m regions, POIs), `terrain` (heightfield, flattening), `roads`, `ruins`, `trees`.
- `world/` — runtime with three.js: player, doors/stairs, enemies, loot, NPCs, `level` (loading places, transitions), `overworld` (chunk streaming, structures, field enemies).
- `ui/` — DOM: HUD, minimap, `worldmap` (surface minimap + M map), backpack, dialogue, menu, input, touch.

## Open world notes
- Regions (rx, rz) span [rx*256-128, rx*256+128); region (0,0) holds Gridholm at the origin. New place types = new `PoiType` + a placement rule in `gen/regions.ts`.
- The planet (`gen/regions.ts`): the world wraps east-west after `NR` = 470 regions (`WORLD_W` ≈ 120 km, canonical x in [`X_MIN`, `X_MIN + WORLD_W`)); north and south it ends at the poles (ice caps from `POLAR_Z` = 25 km: no places, no forest, pale ice lines; an ice wall at `POLE_Z` ≈ 30 km that the player cannot pass). Generators take any coordinates but work in canonical ones: `regionInfo`/`chunkTrees`/`chunkRocks`/`regionVehicle` fold `rx`/`cx` with `wrapR`/`wrapC` and shift the result to the requested copy, so ids and save keys are the same on both sides of the seam; noise repeats through `fbm(..., px)` with scales adjusted by `wrapScale` (near Gridholm the land is practically unchanged). At runtime `keepOnPlanet` moves the player (and vehicles, loot; foes are dropped) to the other copy when crossing the seam and rebuilds the chunks. Distances to saved places use `worldDist` / `nearX` / `wrapDx`. Big static meshes use `localize()` (small local vertices, offset in the object position) so lines do not shimmer tens of km from the origin. The sun's path tilts with `latitude(z)` (`sunTilt`): high at the equator, endless dusk at the poles. Danger is capped at 8.
- Villages (`gen/regions.ts`): Gridholm (`GRIDHOLM_ID`, region 0,0) plus villages on a grid of 10x10-region cells (~2.5 km), sparser the further from Gridholm: `villageChance(d)` 0.8 → 0.22 and a least spacing `villageGap(d)` 1.4 → 5.2 km (the weaker candidate by hash gives way; `candidate` / `villageOfCell`, both cached), `SETTLED` from 6 to 40 km (`allVillages` lists them, ~80–120 per world: none in the mountains or the dead cities), named from syllables, never on the ice. Each is `generateVillage(villageSeed(world, poi), y, x, z, name, home)`: own layout, gates, residents with their own names (`Npc.town`; dialogue swaps 'Gridholm' for the town). Walls come in tiers (`WALL_TIERS` in `gen/village.ts`, `generateVillage(..., tier)`, default 0; not saved yet — village fortification will raise them): 0 Stake Fence (2 m), 1 Timber Palisade (4 m), 2 Stone Wall (7 m, the old voxel wall with towers, battlements and buttresses, `STONE_TIER`). Below stone the wall ring is voxels that only collide (`VillageMap.ops`; the mesh uses `shown`, without them) and `fenceDeco` in `world/level.ts` draws `VillageMap.fence` runs as leaning sharpened stakes, rails and scrap patches, gate frames (sign at `WALL_TIERS[t].gate`) and stilt watch platforms in the corners (`towers`, not solid). Wall shapes (`villageSides(seed, home)`: 4 / 6 / 8 / 12, Gridholm always 4; `wallPolygon(sides)` corners on the wall's middle line in plaza coordinates, `insideWall(poly, x, z, m)`): every shape fits the square footprint; octagon and dodecagon keep the square's flat N/E/S/W sides (apothem 36.5, so gates, `GATE_SLOTS`, roads' `GATE_POINT` are unchanged) and cut its corners; the regular hexagon (R 36.5, flat N/S at apothem 31.6) gets only N and S gates (`villageGates(seed, home)`; roads pass `home`). A polygon wall is voxel runs along its edges (`ringOps`, 4-connected), towers at its corners (every other one of a dodecagon, none by a gate; stilt platforms 3.6 m inside, stone towers straddling the corner), merlons on every other cell pair, fence runs along the edges broken at gates; buildings go round the plaza (`ringLayout`: 36 jittered angles, each building facing the middle, as far out as fits 2.5 m inside the wall, clear of the middle, the gate lanes, other buildings and the towers; shops first, then up to 6 houses); trees and walk cells stay inside (`blocked`, `walk`); `ladderIn` puts a polygon tower's ladder at the inner end of the face towards the middle. The maps draw each village's outline. Every tower has a ladder (`Tower.ladder`, `ladderOf` in `gen/village.ts`: on the face towards the plaza, `top` = deck height, `deck` rect, `stilts`); `world/ladders.ts` draws them (`drawLadder` in `villageDeco`), registers them per loaded village (`setLadders` / `dropLadders`), and climbs: E at the foot or top (`nearLadder`, `startClimb`; not with hands-only items) → `updateClimb` replaces `updatePlayer` (step on, hand-over-hand pulls with sway and two hands on the camera, swing onto the deck; W/S reverse, Space lets go; weapons away via the armed rule `climbing()`); a stilt deck is a floor (`ladderFloor` in `G.floor`) and every tower top has a rail (`ladderHit` in `G.obstacle`, open at the ladder). Lookout roofs over towers stand 2.5 m up (`lookout(..., post)`). Village state (`gen/town.ts`, pure, saved as `char.towns[villageId]`: `wall`, `given`, `fixed`, `hurt`): the elder's option 'fortify' (`renderFortify` in `ui/dialog.ts`) commissions the next wall tier (`FORTIFY` needs, gold, xp; `handOver` takes materials bit by bit, raising the tier when complete, then `reloadStruct` rebuilds the village; `loadVillageStruct` passes `wallOf(state)` to `generateVillage`). Power plants: `powerKind(seed)` generator / solar / wind (`POWER`: name, fix parts, wear per day, pay), `powerSite(seed)` (plaza-local, 17 m outside a W/E/S side, off the gates), `powerCondition` (100 − days since `lastFix` × wear − hurt; never-mended villages start at a hashed age), `POWER_DOWN` 25 / `POWER_LOW` 60. `world/power.ts` draws them (`drawPower`, rotors spin, status light, village lamps named 'lamp' go dark when down), `updatePower` in the main loop, `nearPower` / `repairPower` (E, takes the `fix` parts, pays, xp). Village raids (`gen/raids.ts`, pure, no state but the outcomes you fought): `raidSource` = nearest camp within `RAID.reach` 3.5 km; a timetable per village (`raidOf` / `raidsBetween`: every 2–5 days by hash, none in the first period); `raidOutcome` = the fought result (`TownState.raids[k]`) or a hashed roll against `RAID.hold[wall tier]` (0.45 / 0.7 / 0.9, minus strength); `raidHurt` adds `RAID.loss` 35 per lost raid since the plant was last mended to `powerCondition` (`plantCondition` in `world/power.ts`); `nextRaid` / `lastRaid` for the elder. `world/villageraid.ts` (runtime): within `VRAID.reach` 450 m of a loaded village, warns `RAID.warn` before, then runs a live raid (`LiveRaid`): 3 waves from the camp's direction (~110 m out), bandits with `home` = the nearest gate or the power plant (`ambush = -1`: culled at 240 m, not patrols); at a gate they drain the defences (`VRAID.drain` by wall tier), at the plant they add to `hurt` (at most `plantMax` 45 a raid); all waves dead → won (gold, xp), defences 0 → lost; leaving the village drops the raid (it is then settled by the roll). `raidHere()` makes the village unsafe (`foeRules.playerSafe`, the armed rule), `raidLine` in the tracker, console `raid` (a test raid, k 0, not recorded). Tribute: `tribute(r, wealth, wall)` in `gen/raids.ts` (60 + 45·strength + 0.3·storehouse value, −18% per wall tier, rounded to 10); the warning is a rider's demand (`pendingTribute`, `payTribute` in `world/villageraid.ts`; buttons in the elder's and the guard's panels, `data-tribute`; the demand in `raidLine`); paid = `TownState.raids[k] = 'paid'` (no raid); unvisited villages sometimes pay (`raidOutcome` 'paid'). In a live raid gunners at their gate shoot the wall (`shelling`: tracers, defences −0.35 a burst) and now and then a villager in the open (`killVillager`, `updateFallen`, `TownState.dead` times: `recentDead` villagers are missing for 2 days); a lost live raid drops the wall a tier (`reloadStruct`). Industries (`gen/industry.ts`, pure): `industryOf(world, poi, seed)` = farm / mine / oil / refinery / lumber / fishery / workshop / salvage (weights by distance from Gridholm and hills; a farm/workshop/salvage village with an oil village within 9 km becomes a refinery town 45% of the time); `INDUSTRY[k]` = site name, `pool` of goods it makes (the market picks up to 2), goods it `wants`, `fix` parts, `build` (refinery). `industrySite(seed, k)` (plaza-local, on another W/E/S side than the power plant, 11 m + half its depth out: inside the tree clearing). `siteCondition` = 100 − lost raids (`SITE.raid` 40, healing over `SITE.heal` 4 days) − bandit damage at the site (`TownState.siteHurt/siteHurtT`, same healing), reset by `siteFixed`; `production` = condition / 100, 0 for an unbuilt refinery (`siteBuilt`, `TownState.built`); `buildPlan` / `handOverBuild` (elder commission, `REFINERY_PAY`). `quote(..., prod)` makes a damaged site's goods scarcer and dearer, none while unbuilt. `world/industry.ts` draws the sites (fields with crop rows, mine adit + headframe + rails + cart, pumpjacks with nodding beams + tanks, refinery columns / tanks / flare or its scaffolded building site, sawmill, fish racks, workshops, salvage yard; a sign), `updateIndustry` animates by production, `nearSite` / `sitePrompt` / `repairSite` (E). Live raids send a third of the bandits at the site. Workers (`Worker` in `world/industry.ts`, figures with kits 'hoe' / 'pick' / 'hammer' / 'carry' from `world/rig.ts`): 3–4 per site walk between the site's work spots and work there (a stroke every ~1.2 s), one carries crates to the storehouse door; idle when the site does not work; placed relative to the localized village group (`localize`). The village's own goods (what its industry makes) pile up in its village hall (see Village halls: `gen/hall.ts` `OWN`, `stockOf`); the old industry storehouse, its tiers, shipments and convoy are gone. While the village's own goods are ≥ 75% of their cap (`glutted` in `ui/market.ts`) they sell wholesale (`WHOLESALE` 0.8, +20 stock); buying them, the elder's share and loading a haul take them out of the hall (`takeOwn`). Trade (`gen/market.ts`, pure): goods are items of type 'good' (15 `GOODS`, `GOOD_INFO` base prices, raw/made; stack 5, bulky `BULK`); `profileOf(world, poi, seed)` = 1–2 goods a village makes (from its industry's pool) and 2 it wants (the industry's wants, fuel for a diesel generator, the rest weighted by distance from Gridholm); `quote(...)` = buy/sell prices and stock (base × make 0.6 / want 1.6 × slow drift × glut from the stock shift, ± spread); `MarketState` (`char.market`, keys `villageId:good`, `{d, t}`) is the only state: `trade` adds crates sold (+) / bought (−), shifts decay with `MARKET.half` 36 h, `tidyMarket` prunes. On the multiplayer server this state is shared = global economy. `ui/market.ts` (merchant option 'trade' in every village, wide `#dlg .panel.wide` table): buys into the backpack then trunks of owned vehicles within 90 m (`stores`), sells from them, one crate at a time so each moves the price; `char.ledger[villageId]` records prices seen (best price elsewhere per good, distance, age); hearsay names the 2 nearest unseen markets within 9 km and what they want. Delivery contracts (`gen/contracts.ts`, pure): `offersAt(world, poi, seed, now)` = `CONTRACT.perVillage` 2 offers per posting (`CONTRACT.period` 12 h, fixed at the posting's start): supply (a good the village wants, n crates, pay = its sell price × `premium` 1.35) or haul (a good it makes to a village 2–9 km off, preferring one that wants it; pay per crate by distance and danger; deposit = n × buy price). `payFor` (a finished haul returns the deposit). `ui/contracts.ts` (merchant option 'contracts'): `char.contracts` (max 3) and `char.taken` offer ids; taking a haul pays the deposit and loads the crates trunks-first (`putAway(..., true)` from `ui/market.ts`, whose `stores` / `carried` / `takeFrom` take a place); handing over at the destination's store pays per crate and moves its market (`trade`); `updateContracts` fails overdue ones; `contractLines` in the tracker, `contractMarkers` in `questMarkers` (compass, maps). NPC caravans (`gen/caravans.ts`, pure, no state): every road edge has a timetable (`CARAVAN`: period 6–16 h by hash, 25% of departures skipped, departures alternate a→b / b→a, speed 7 m per game minute along `edgePath`), `caravanOf(world, edge, k)` (cargo: what home makes, preferably what the destination wants; 1–3 wagons), `departures`, `onRoad`, `caravanS`; `caravanShift` (departure −n, arrival +n, × `weight` 0.25, decaying with `MARKET.half`) feeds `quote` (`caravans` flag), `lastArrival` feeds the merchant's news. a caravan is a convoy (`CONVOY`: gun jeep, Mastodon truck with the cargo 12–30 crates, gun jeep; `back` offsets 0 / 8.5 / 17 m used by `caravanS`). `world/caravans.ts` draws the convoy (`convoyModel` from `world/vehicles.ts`: body, wheels, roof cannon; per-vehicle boxes `SIZE`; the jeeps' guns `aimGun`/`CONVOY_GUN` turn to the nearest raid bandit or, with none left, a barricade within 30 m, and fire: tracer, noise, `shootBandit` without bounty) on `regionRoads` near the player (`updateCaravans` in the main loop, rescans twice a second, keeps to the right, pitch from the terrain), `caravanHit` in `G.obstacle` plus a shove, `nearCaravan`; `ui/caravan.ts` (E): route, cargo, arrival time, buy crates at the midpoint of the two markets' prices (`char.caravans[id]` = crates bought). Raids (`world/caravans.ts`, runtime only: `Live` per caravan: `delay`, `hp`, `raid` bandits, `rolled`): a caravan coming within 160 m rolls once (`CARAVAN_RAID`: 12% + 4% per danger, from danger 1.2, through `mayspawn`); `startRaid` spawns 3+ bandits beside the lead wagon (`sight` 60) and a roadblock 16 m ahead (`placeRoadblock`); the convoy also halts while a barricade stands within 9 m ahead of it; while any are within 45 m the caravan halts (`delay` grows) and loses `drain` hp per bandit per second; at 0 it is plundered (`char.caravans['lost:<id>']`, never drawn again, nothing to buy); when the raid is over with at least half the bandits killed it is saved (gold, xp, `saved:<id>` → 30% off its cargo). Escort (`char.escort`, `takeEscort` from the drover's panel while the caravan has done < 35% of its road, pay `escortPay`): a guaranteed raid past 30% of the road, a second one (50%) past 72%; `escortTick` pays on arrival if you are within 400 m of the destination, fails if the caravan is plundered or you stay 350 m+ away for a minute; `escortLine` in the quest tracker. Maps: `mapWagons` (minimap and map, gold = your escort, red rim = raided), the big map draws every caravan on roads between known villages from the timetable (`caravanPos`, at most 2 new road paths per frame via `pathKnown`). The hero's house (Gridholm only): the house at plaza (3, 43) is `YOUR HOUSE` (`Building.mine`; the sign reads FOR SALE and the door is padlocked until the elder sells it: option 'house', `renderHouse` in `ui/dialog.ts`, `HOUSE_PRICE` 750 in `data/npcs.ts`, `char.houses` village ids; saves that already used the home chest get it free; the chest, bed and waking in your bed need it), `VillageMap.house` holds its bed and chest (world); `world/home.ts`: E at the chest opens the transfer window on `char.containers['home:chest']` (`HOME_CHEST_SLOTS` 24), E at the bed sleeps (`sleepSpan` / `SLEEP` in `data/survival.ts`: from 20:00 to 06:00 until 07:00 with full HP, else a 2 h nap; kcal/water/stomach run on at the sleeping rate); recall to Gridholm arrives by the bed (`Arrival` tavern `bed`); death wakes you in your cryo-pod (see the story). Only Gridholm (`VillageMap.home`) has Kuba's yard for now; every village has a notice board. Safe zones, holstered weapons and the no-spawn margins apply around every village (`villageContaining`, `villageDist`). The Recall Beacon takes you to the nearest village you have explored (`toVillage`); death (`toVillage('death')` with no id) wakes you in your cryo-pod aboard the crashed ship; console `home` = Gridholm. Future multiplayer: villages (and later crash sites) are the spawn points.
- Wall-walk and defence works: `WALL_TIERS[t].walk` (palisade 3.3 m, stone 5.6 m; none behind a stake fence). `generateVillage` gives `VillageMap.walkway` (`WalkRun`: the fence runs on the wall's middle line trimmed clear of corner towers (4.5 m) and a stone wall's gate towers, `nx/nz` into the village, deck `WALK.in0`..`in1` 0.5–1.7 m inwards), `walkLadders` (`Ladder.walk`: one per run, two on runs > 28 m, nudged to free ground by `clear`) and `mounts` (`Mount`, turret spots on the wall top: by the gates first, then run middles, `MOUNTS_MAX` 6), all from `wallWalk` in `gen/village.ts`. `world/walkways.ts`: `setWalkways` / `dropWalkways`, `walkFloor` in `G.floor`, `walkHit` (inner rail open at ladders, end rails) in `G.obstacle`; ladders register with the towers' (`ladderHit` skips `walk` ones); `walkwayDeco` in `world/level.ts` draws deck, planks, posts with knee braces, rail and toe board. A palisade's stakes stay 3.2–4 m so you shoot over them from the walk. Defence works (`gen/town.ts` `WORKS`, `workPlan` / `handOverWork`, `TownState.works` / `wgiven`, `worksOf`): 'turret' (Turret Kit + circuits + wire + scrap, up to the village's mounts; `BASE_ITEMS` no longer hides the kit), 'siteGuard' and 'plantGuard' (sandbag barricades); the elder's fortify panel lists them (`defenceText`, `defenceRows`, `giveWork`, `data-work`) and `reloadStruct` rebuilds. `world/wallguns.ts` (runtime; loads through `villageHooks` in `world/overworld.ts` to keep overworld free of the player/enemies import chain): a braced platform with a steel ring, ammo box and twin-barrel head per turret, targets hostile `foes()` within `WALL_GUN.range` 60 m in sight (`rayWorld`), fires via `damageFoe`; idle it sweeps outwards. `world/siteguards.ts` `drawGuards` (with the village group): sandbag walls 3 courses high round the site / plant (open towards the village), steel hedgehogs and spiked timber outside, `guardHit` in `G.obstacle`. `GUARDED`: bandit damage at a guarded site/plant in a live raid ×0.35, a lost raid's damage ×0.5 (`siteCondition`, `raidHurt`).
